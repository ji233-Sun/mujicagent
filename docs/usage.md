# 使用指南

[返回产品介绍](../README.md) · [开发指南](development.md)

## 安装与更新

安装包在 [GitHub Releases](https://github.com/ji233-Sun/mujicagent/releases)：Apple Silicon 选择 `arm64.dmg`，Intel 选择 `amd64.dmg`。将应用拖入可写的 Applications 目录后运行；磁盘映像内、开发模式或不可写目录不支持自动安装更新。

Windows x64 选择 `mujicagent-setup-<版本>-amd64.exe`，Windows ARM64 选择 `arm64.exe` 安装器。默认安装在 `%LOCALAPPDATA%\Programs` 下的用户可写目录，支持下载签名更新并重启安装。Windows 安装器和应用目前未配置 Authenticode 代码签名，系统可能显示未知发布者或 SmartScreen 提示；更新归档仍使用与 macOS 相同的 Ed25519 密钥签名校验。

应用启动 10 秒后检查正式 Release，随后每 24 小时检查一次；**设置 → 软件更新**也可手动检查。发现新版本后，左下角出现更新入口。点击“下载更新”，由 MyGo 下载对应架构的包并校验签名，再点击“重启并更新”；有对话运行时暂停安装和重启。更新不改动本地项目、会话和 Codex。更新日志使用原生 Markdown 展示最近 20 条正式 Release，旧版本可展开查看。

## 智能体安装与更新

打开 **设置 → 智能体**，已有安装显示版本与来源。VP/npm/Bun/pnpm/Homebrew 安装沿用原工具更新，托管安装沿用原渠道；点击“更新”先预览指令和安装路径，再点击“确认更新”执行。应用核对包管理器的全局目录及实际安装归属；未适配的工具、未知来源、工具不可用或来源冲突会明确提示，不自动迁移安装。自动检查默认每天一次，可关闭，只查版本、不安装。

未安装时点击“安装”，在统一弹窗中选择当前智能体支持的渠道，预览后确认安装；设置页不常驻下载方式。Codex 提供官方原生包、大陆 npm 镜像、大陆免 Node 镜像包；Pi 提供官方原生包、官方 npm、大陆 npm 镜像；Droid 提供这四种渠道。Pi npm 要求 Node.js ≥ 22.19，Droid npm 要求 Node.js ≥ 20，缺少运行时可选择官方原生包。镜像缺包时显示错误，不在执行时静默切换来源。新安装写入应用私有目录；无 npm 或 Windows 下的镜像原生包方式会在确认前显示下载动作、地址、摘要和安装路径，不执行 curl 或 shell 安装脚本。下载先校验摘要、完整解包并验证版本，再切换路径；安装可取消，失败保留旧配置。Windows 更新前关闭 App Server，托管版本写入新目录，避免覆盖占用中的 exe。有对话运行时不能更新。

Pi 官方脚本安装沿用其自更新命令；Droid 独立原生安装按预览版本自更新，Homebrew 安装沿用 cask。Factory.app 内置 Droid 和 Nix 安装显示来源及原工具更新提示。Pi/Droid 安装更新不会断开 Codex 连接。

## 连接 Codex

认证沿用 [Codex CLI](https://developers.openai.com/codex/cli) 的登录或配置：支持 ChatGPT、API key，以及 config.toml 中的自定义 base_url/env_key。密钥由 Codex 管理，应用不复制或展示；环境变量需在启动应用的环境中可用。无需 OpenAI 登录的服务商不会显示强制登录提示，配置状态不代表密钥已验证。账户路由发现超时最多重试三次，间隔 500ms、1s；其他认证错误不会重试。

应用默认寻找 PATH 中的 `codex`。macOS 下会读取用户登录 Shell 的 PATH，供 Codex 及其 Node 等运行时使用，因此从 Finder、Dock 启动也能找到终端中安装的 CLI；探测有超时限制，并保留原有 PATH 和常见安装目录。也可在 **设置 → 智能体（Agents）→ 连接与权限 → 可执行路径** 指定绝对路径，应用不会自动替换该选择。

## Pi、Droid 与会话交接

**设置 → 智能体**的二级侧栏分别管理 Codex、Pi 和 Droid，三者复用同一安装卡片、版本检查、确认弹窗、错误及取消流程。Pi/Droid 可在应用内安装；登录仍按 [Pi 官方指南](https://pi.dev/)或 [Droid 官方指南](https://docs.factory.com/droid-cli/quickstart)完成，也可填写已有可执行路径（留空查找 `pi` / `droid`）。「可用」只说明 CLI 已探测到，账户行明确标记尚未验证登录。设置页只管理 CLI，模型在对话输入栏选择。应用不修改全局 PATH、不复制凭据。Windows 的 Pi 官方托管/npm 启动器解析为 Node + 已知包内脚本，Droid npm 启动器解析为平台包原生 exe；未知 `.cmd` / `.bat` 不执行。

输入栏模型浮层左侧是 32px 图标栏，悬停显示名称；浏览图标不会改变会话。切换 Harness 时自动通过其本机 CLI 读取可用模型（包括已配置的自定义模型），复用 Codex 的搜索列表，点选即使用。列表只展示具体模型，不提供「默认模型」或手填 ID 入口。Pi 使用 `get_available_models`，Droid 使用 `droid.list_models`，不创建会话、不发送模型请求。列表按当前可执行文件和项目目录缓存，支持刷新；失败时显示重试入口，旧版 Droid 可能需要更新。设置页采用紧凑卡片，路径位于折叠详情中。

Pi/Droid 的思考控件随模型目录变化：多个档位显示紧凑选项，只有一个档位时显示固定值，只有关闭/开启两种能力时显示开关，无可用思考能力时显示不可用状态。Pi 的 `thinkingLevelMap` 中 `null` 表示不支持，不能据此补出 `off/low/medium`；未指定的标准档位按 Pi 官方规则继承。Droid 保留目录的原始档位和默认值，开关也回传真实值，例如 `none/high`。同 Harness 换模型保留兼容选择；刷新会修正并保存过期档位，跨 Harness 不继承旧选择。CLI 未提供默认值时明确显示「默认」，不猜测当前开关状态。

已有对话选择其他 Harness 后，点选目标模型创建关联的新会话，带入可见的用户消息、回复、计划和后续引导，沿用项目目录，下一次发送时才交付上下文。原会话、草稿和待发队列保留；队列不会复制或自动执行。新会话不继承原服务端 session ID、审批或工具权限；标题栏「原会话」可返回来源。交接不迁移隐藏推理、完整工具日志或 CLI 私有状态，超过 512 KiB 的上下文会要求手动摘要，不静默截断。运行期间需先停止任务，才可交接。同一 Harness 内换模型沿用现有会话，下一轮使用新模型。

Pi 使用双向 RPC，Droid 使用官方 `stream-jsonrpc`。回复、思考、工具开始/进度/结果按稳定 ID 保存，复用统一时间线和可展开详情；普通工具不标成 MCP，缺失的服务元数据不猜测。参数和结果在保存前经过现有脱敏处理。Pi 压缩事件、Droid 压缩状态及 TodoWrite 计划归入过程记录；最终消息快照替换对应消息，不覆盖先前工具与回复。

Pi 默认只开放内置读取和搜索工具，并关闭扩展与 MCP；完全访问沿用本机工具配置，没有操作系统沙箱。RPC 扩展的确认、选择和输入在应用内回答，编辑框支持预填与多行，超时会取消请求并清理界面；这不代表所有 Pi 工具都有逐次权限拦截。Droid 每轮显式设置 `interactionMode=auto`，四档权限对应 `autonomyLevel=off/low/medium/high`；运行期间修改权限在下一轮生效。权限请求进入确认界面，仅在上游提供 `proceed_once` 时显示一次允许，不自动永久授权；AskUser 支持多选、补充文字和取消，扩展 picker 支持单选/多选、预选、搜索、刷新和取消，按原始选项 ID 回传。

Pi 工具事件中的 MCP `server/tool` 和 Droid 审批详情中的真实 MCP 元数据会保留，后续进度不会将已识别的 MCP 降回普通工具。Pi 已启用官方 plan-mode 扩展时，其 `plan-todos` 组件可显示为计划；Droid TodoWrite 显示可读待办。计划文本可随会话交接，但这不等于两者具备统一的计划执行模式，也不会自动安装 Pi 扩展。

两个 Harness 的运行中插入消息通过各自官方协议发送，收到成功确认才移除本地队列；发送失败保留消息。停止会取消进程和待答请求，将未完成过程标为中断；失败/停止不自动发送后续队列。图片使用 MIME 与 base64 传输，普通文件继续使用本地路径。模型与思考强度下一轮生效。

完整能力对齐仍由 [#84](https://github.com/ji233-Sun/mujicagent/issues/84) 跟踪：当前协议回放与界面测试不能代替真实 CLI/模型验收。速度档位没有当前 RPC 的等价配置；通用 MCP elicitation 尚未接通（[Pi 明确未支持](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/test/mcp-conformance/README.md)，已核对的 Droid 协议未公开对应客户端请求）；Droid 无审批详情的工具事件仍可能缺少 MCP 服务名。计划执行模式与三 Harness 真实工作流仍待验收。Pi/Droid 的应用内安装更新已接入同一流程；两者仍缺少已验证的应用内账号状态与登录协议。

模型行右侧的星标用于收藏，按 `(Harness, Model ID)` 精确保存并在所属 Harness 的列表内置顶。同名模型在不同 Harness 中互不影响。左侧最上方的星标入口汇总全部收藏，行首显示所属 Harness 的官方图标；普通列表不显示行首图标。收藏、取消收藏不切换当前模型，重启后保留。

## 界面与会话

- 原生毛玻璃侧栏、紧凑单行会话、统一浅色界面（不跟随系统深色）；悬停高亮，遵循系统“减少动态效果”设置。
- 项目以可折叠文件夹显示，默认折叠并在重启后记住展开状态。每个展开区最多显示十行会话，其余通过滚轮查看；列表只构建可见范围及少量预加载行。悬停项目行时，箭头旁显示新建会话的 `+`。
- 添加本地项目，也可通过「无项目／No Project」分组开始对话；该分组使用虚线文件夹图标，支持折叠与新建，对话仅在手动收纳后进入收纳箱。
- 手动**收纳（Settle）**：悬停或右键收纳会话；底部“收纳”显示数量，点击向上展开，最多显示五行，其余通过滚轮查看。列表只构建可见范围及少量预加载行，完成回复不会自动收纳。
- 会话右键删除，必须经过二次确认。删除本应用的会话记录，保留项目文件和 Codex 自身的历史。
- 本地 Codex App Server 连接、模型与思考强度选择、流式 Markdown、代码块、执行过程、停止生成、重连后继续会话。
- 正式回复之间的思考、命令、文件更改等合并为默认折叠的过程框，按类型显示次数与 Lucide 图标；可逐层展开，失败操作有独立标记。
- MCP 调用显示工具名、服务名、参数摘要和执行状态；展开可查看参数、结果和错误，较长内容可滚动查看。缺失数据会明确提示，历史记录中未保存的详情无法补回。参数、结果和错误中的常见敏感字段、认证头及私钥在保存前脱敏；没有字段标识或认证格式的任意文本无法保证识别。
- **Ask**：选项或自由输入、多问题、私密输入。命令／文件审批支持允许本次、会话内允许、命令前缀规则、网络主机规则及拒绝，具体选项由 App Server 的审批请求决定；通过原始请求 ID 回传。
- 按对话选择只读、默认权限、自动审批（Approve for me）或完全访问，并展示服务端提供的自定义权限档位；遵循服务端管理策略，完全访问需要确认。
- 原生设置悬浮面板：保留背后的对话，右上角关闭或按 Esc 返回；Agents 使用紧凑二级侧栏管理 Codex、Pi、Droid；三者卡片统一提供安装来源、版本检查、安装更新和可执行路径；连接与账户信息按真实能力显示。
- 项目、会话、草稿和 Settle 状态保存在本机。
- 启动后自动检查 GitHub Release；设置中可下载签名更新、重启安装并查看历史更新日志。
- 简体中文／英文即时切换，默认中文；菜单、设置、Ask 操作及原生控件跟随语言，用户内容保持原文。

## 对话与附件

点击输入框右侧的 `+` 选择图片或文件，也可直接粘贴复制的文件或图片。附件以小缩略图／文件图标和文件名嵌入正文，不带底色或下划线；前后文字在同一输入框连续编辑，支持选择、复制、退格删除和撤销。发送后保持相同的行内样式。剪贴板图片保存到应用数据目录，普通文件保留在原位置。

图片使用 Codex 的 `localImage` 输入；普通文件仅传递本地绝对路径，由 Agent 按当前权限读取。支持预览 PNG、JPEG、GIF 首帧、WebP 和 BMP；无法解码或超过预览限制（32 MiB／2400 万像素）的文件作为普通文件插入。文件保留在原位置，移动或删除后可能无法访问。未知扩展名使用通用 Lucide 文件图标。

点击图片附件打开标注工作区：支持适应窗口、1:1、缩放、平移，以及画笔、矩形、箭头和位置评论。右侧列表集中编辑说明；选择一条评论并开启「新图形关联到此评论」，可让多个图形共用一个编号和说明。也可添加整张图片的说明。选择工具可点选或拖动标注，工具条支持撤销、重做、颜色和粗细。关闭未应用的编辑前会提示确认。

点击「应用到当前草稿」后，草稿中的附件原位更新，已发送的消息保持原样；消息编辑器撤销可恢复原附件。发送时提供原图、带编号的标注图和对应的评论文字，原文件不会被覆盖。标注使用相对于图片左上角的百分比坐标，随附件链接保存，兼容旧的单点说明。内部链接格式为 `<mujica://image/?path=...>` 或 `<mujica://file/?path=...>`，路径及标注参数使用 URL 编码，仅在应用内解析。

在 **设置 → 日志** 查看本次运行的日志，最新记录在前，最多保留 200 条，不写入磁盘。开发者模式默认关闭；打开后才显示暂不支持的 Codex 请求等诊断记录，开关会保存到本机。普通日志不再占用页面顶部。

找不到 Codex、连接失败等错误不受开发者模式限制：主界面右上方显示红色浮动通知，包含错误图标、标题、正文和关闭按钮。打开设置时可在日志页查看错误，关闭通知不删除日志。

点击「无项目」分组旁的 `+` 新建无项目会话，或用左下角文件夹按钮添加项目，再点击项目旁的 `+`。Enter 发送，Shift+Enter 换行。

对话进行中可继续发送，消息进入输入框上方的等待队列。拖动左侧手柄调整顺序；正常完成整轮后，只发送下一条。点击「插入对话」通过 `turn/steer` 引导当前轮，由 Codex 在工具调用边界处理；成功后从队列移除并显示在当前轮记录中，失败保留原消息。停止、失败、断线或重启后队列暂停，可点击「继续发送」。队列保存在本地；普通发送和 Steer 共用附件解析与当前会话上下文。

队列卡片支持直接删除和编辑。点击编辑后，消息回到输入框，保存时更新原来的队列位置；取消或按 Esc 恢复普通草稿。编辑期间轮到该消息时暂停发送，保存后可点击「继续发送」。未保存的编辑只在本次运行保留，原消息和普通草稿不受影响。正在发送的消息不可编辑或删除。拖动手柄或卡片正文时，整张卡片跟随鼠标，原卡淡化，目标卡片高亮并显示上方或下方的插入线；释放后保存顺序，按 Esc 取消拖动。

点击输入框底部的 `模型 · 思考强度 · 速度`（普通速度不额外标注），面板以 220 毫秒淡入并轻微上移，关闭时以 160 毫秒淡出并轻微下移。左侧选择或搜索模型，右侧通过原生分档滑块调整强度，刻度来自该模型支持的档位，支持拖动和方向键。兼容的强度会保留，否则切换到模型默认值；调整时保持面板打开，点击外部或按 Esc 关闭。启用系统“减少动态效果”时直接显示或关闭。

面板右下角的 Fast／Ultrafast 上下排列，每项占一整行，来自 App Server `model/list` 的 `serviceTiers`，只显示当前模型提供的速度选项。点击切换，再次点击取消，均未选中时使用普通速度；换模型会保留兼容的速度，否则恢复普通速度。选择保存在本机，并通过 `turn/start.serviceTier` 传递服务端返回的 ID；普通速度明确传递 `default`，避免继承之前的加速设置。

在**设置 → 外观 → 语言**选择简体中文或 English，立即生效并保存。空白会话在中文显示“新对话”，收纳入口显示“收纳”；切换英文后分别显示“New conversation”和“Settled”。模型名称、思考强度代码、用户标题、对话内容和外部错误详情保持原文。

输入框旁的权限选择器通过 `permissionProfile/list` 按当前项目读取档位，结合 `configRequirements/read` 的审批策略限制禁用不可用选项。新建对话默认使用工作区权限；选择单独保存在该对话中，不影响其他对话。权限通过 `thread/start`、`thread/resume` 和每次 `turn/start` 的 `permissions`、`approvalPolicy` 传递。已加载的会话调整权限时，通过 `thread/settings/update` 提交后才保存新选择；失败时保留原选择并显示错误。

运行期间也可以为下一轮调整权限，选择器显示“当前权限 → 下一轮权限”，面板说明生效边界。Codex CLI 0.167.0 的 `thread/settings/update` 仅更新后续轮次；`turn/settings/update` 不支持权限档位或审批策略，因此本轮尚未开始的操作也仍使用本轮原权限。正在执行的操作、待处理审批和子会话均不会因选择变化而自动获得授权。下一轮显式发送新权限，保留原会话上下文；无需新建会话或重启。轮次启动中暂不能修改，需稍后重试。完全访问仍需确认，不更改全局默认权限。

自动审批沿用工作区权限和 `on-request` 策略，将 `approvalsReviewer` 设为 `auto_review`，由 Codex 审核审批请求。只有服务端启用 `guardian_approval` 时才显示，并遵循项目配置及 `allowedApprovalsReviewers` 限制；切回默认权限后由用户审批，不修改全局 Codex 配置。

每次对话显式请求 `summary: auto`，展示 App Server 返回的思考摘要。模型不保证每次都返回摘要；展开空记录时显示“未返回思考摘要”，进行中的空记录显示“等待思考摘要…”。历史记录中没有返回的内容无法补回。

对话使用默认协作模式，不再提供“计划”开关。Ask 出现后选取答案或直接输入，再点击“继续”。审批卡片优先使用服务端 `availableDecisions`：会话内允许仅作用于服务端定义的匹配范围；记住命令规则会显示前缀，网络规则会显示主机。未提供决策列表时按相应协议生成选项，绝不自行将一次允许提升为会话或永久授权。

## 范围与限制

当前验证环境是 macOS arm64、MyGo 0.7.4、Codex CLI 0.167.0。Windows、Linux 尚未做运行验证；毛玻璃使用系统提供的材质，不支持材质的平台使用实色侧栏。

此版本不包含 MCP 管理、remote、worktree 或多个 Codex 实例。现有 Codex 用户配置仍由 Codex 自身加载。Ask 等协议仍在演进，需要支持对应 App Server API 的 CLI。

应用非正常关闭时，未完成回复可能只保留最近保存的本地快照，重启后标为中断；已保存会话可重连继续。尚未实现从 Codex 的全局历史导入或同步其他客户端的修改。
